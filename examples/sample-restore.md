# Restore plan (sample)

Generated by `comfyguard restore baseline.json --target /opt/comfyui` (dry-run).
Ruleset 2026.08.1. This plan rolls the instance back to the state captured in
`baseline.json` (2026-08-03, a clean grade-A snapshot).

ComfyGuard wrote this plan, the script `restore.sh`, and a Manager-format
snapshot copy. It changed nothing. Running the rollback is a separate, deliberate
step: either execute `restore.sh` (a human, a coding agent, or CI), or re-run with
`comfyguard restore baseline.json --target /opt/comfyui --apply` to have
ComfyGuard perform it under its guardrails.

## What a rollback has to cover

The Manager snapshot format restores custom nodes and pip packages, but its modern
restore path leaves two gaps that this plan fills:

1. It does not re-checkout the core ComfyUI commit. The plan adds an explicit
   `git checkout` of the recorded core commit.
2. Its pip restore is off by default and always skips torch and nvidia. The plan
   passes the pip flags and emits the exact install lines, including torch.

It also re-applies the launch flags and `security_level` that the Manager format
does not carry.

## Phases and gates

**act-r1 (review-required) Take a fresh pre-restore snapshot.**
Capture the current state first, so the rollback itself is reversible. Written to
the output directory. `comfyguard snapshot /opt/comfyui --out ./pre-restore`.

**act-r2 (review-required) Restore nodes and pip via ComfyUI-Manager.**
`comfy node restore-snapshot ./baseline-manager.json --pip-non-url`. This pins
custom nodes back to their recorded commits and registry versions, and restores
non-torch pip pins. Nodes present now but absent in the baseline (for example a
planted `ComfyUI-Upscaler-4K`) are quarantined by moving them aside, never
deleted.

**act-r3 (review-required) Re-checkout the core ComfyUI commit.**
`git -C /opt/comfyui checkout 7c0d1e2` (the baseline `core.commit`). A dirty
working tree is quarantined, not discarded. This fills Manager gap 1.

**act-r4 (review-required) Reinstall the torch and nvidia pins.**
Manager skips these, so reinstall them explicitly from the snapshot's pinned
versions with hashes where available. This fills Manager gap 2.

**act-r5 (review-required) Re-apply launch flags and Manager security level.**
Restore `--listen 127.0.0.1` in `deploy/comfyui.service`, and set
`security_level=strong`, `allow_pip_install=False` in `config.ini`.

**act-r6 (human-only) Restart the service.**
Redeploy or restart is never automatic. A person restarts and confirms.

**act-r7 (review-required) Verify.**
`comfyguard diff --against baseline.json /opt/comfyui` should return an empty
diff, proving the instance matches the baseline again, including the core-commit
and torch compensations.

## Decisions left to a person

- Whether the pre-restore state contains anything worth preserving before rolling
  back (evidence, new legitimate work).
- Whether to keep any node that appeared after the baseline, rather than
  quarantining it.
